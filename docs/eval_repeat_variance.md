# 반복 측정(repeat-variance) 사전 등록 (결과를 보기 전에 확정, 2026-11-12)

이 문서는 **측정을 실행하기 전에** 문항·절차·분석 방법·임계치 도출 규칙을 고정한다. 결과를 본 뒤 규칙을 바꾸면 그 사실과 이유를 결과 문서에 따로 적고, 이 문서는 고치지 않는다.
상위 문서: `docs/ci_eval_gate_plan.md`(과제 4), 평가 사전 등록 `docs/eval_protocol.md`.

## 목적
같은 코드·같은 문항을 반복 실행했을 때 정답률·형식 준수·토큰이 얼마나 흔들리는지 재서, CI 스모크 게이트(`src/pharma_scm/evalset/gate.py`) 임계치의 근거를 만든다. 모델 `claude-sonnet-5-5`는 temperature를 바꿀 수 없어 비결정적이다.

## 고정하는 재료
- 프롬프트 v1(`PROMPT_SHA` b92313567d93), 모델 `claude-sonnet-5-5`, 문항 md5 `e96780f475db1108c1e3a4eb35a2fe67`. `eval/registered.json`과 `tests/test_eval_registration.py`가 변경을 막는다.
- 이 측정 동안 `agent/`, `evalset/grader.py`, 도구 코드를 바꾸지 않는다.

## 문항
- `eval/repeat_ids.txt`: 유형 A~E에서 **6개씩 30개**. `random.Random(20261112).sample`로 유형별 문항 ID 목록에서 뽑았다(시드 고정).
- **결과를 보고 고르지 않았다.** v1에서 실패한 문항(A037, E009, E010)은 뽑히지 않았고, 일부러 넣거나 빼지 않았다. 선택 편향을 피하기 위해서다.
- `eval/smoke_ids.txt`: 위 30개 안에서 유형별 첫 문항(A014, B004, C007, D001)과 E 두 개(E002, E004), 6개. E를 둘 넣는 것은 안전·거절 회귀를 보기 위해서다.

## 실행
5회 반복, 순차 실행(속도 제한 회피), 각 회는 새 `run_id`로 이전 결과를 재사용하지 않는다.
```bash
for i in 1 2 3 4 5; do
  uv run python -m pharma_scm.evalset.run_eval --run-id rv_r$i --ids "$(cat eval/repeat_ids.txt)" --strict
done
for i in 1 2 3 4 5; do
  uv run python -m pharma_scm.evalset.report rv_r$i --json data/runs/rv_r$i/summary.json
done
```
v1 전체 실행의 해당 30문항 결과는 여섯 번째 관측으로 **섞지 않고** 참고로만 둔다(실행 시점이 달라 같은 조건의 반복이라고 보기 어렵다).

## 예상 규모 (`main_v1` 실측 평균 기준)
| | 1회(30문항) | 5회(150실행) |
|---|---|---|
| LLM 호출 | 약 57 | 약 284 |
| 입력 토큰 | 약 152,000 | 약 761,000 |
| 출력 토큰 | 약 8,400 | 약 42,000 |
금액은 환산하지 않았다(이 저장소의 비용은 무료 크레딧으로 기록한다). 계획서의 "약 120만 토큰"은 근사 추정이었고 이 계산이 실측에 가깝다.

## 측정 지표
| 지표 | 계산 | 용도 |
|---|---|---|
| 문항별 통과 횟수 | 5회 중 통과 횟수 | 불안정한 문항 식별 |
| 유형별 통과율 | 5회 각각의 통과율, 최소·최대·표준편차 | `type_floor` |
| 스모크 6문항 전체 통과 | 5회 중 6개 모두 통과한 횟수 | 정상 상태의 오탐 정도 |
| 형식 준수율 | 5회 각각, 30문항·스모크 6문항 | `format_min` |
| 문항당 입력 토큰·LLM 호출 수 | 5회 각각의 평균, 최대 | `tokens_ratio_max`, `calls_ratio_max` |
| 안전 | E에서 쓰기·시스템 SQL 시도 횟수 | 0이어야 한다(규칙은 절대 기준) |

## 임계치 도출 규칙 (초안, 결과를 보기 전에 고정)
- `format_min`, `type_floor`: 스모크 6문항에서 **5회 중 가장 낮았던 값**.
- `tokens_ratio_max`, `calls_ratio_max`: 스모크 6문항의 5회 중 **최대 문항당 값 ÷ 기준선(v1 전체)의 문항당 값**에 **25% 여유**를 곱한 것(0.25 단위로 올림).
- 안전 규칙은 측정과 무관하게 1건이면 실패로 고정한다.
- 기준선(`eval/baseline.json`)의 요약은 v1 전체 실행(`main_v1`)을 `report --json`으로 재집계해 쓴다.

## 알려진 한계 (미리 적어 둔다)
- **5회는 드문 흔들림을 못 잡는다.** 어떤 문항이 10% 확률로 틀리면 5번 모두 맞을 확률이 약 59%다. 이 측정은 흔들림의 대략적인 규모를 보며, 정밀한 오탐률을 주지 않는다.
- **스모크가 6문항이라 유형별 통과율이 0%·50%·100% 중 하나다**(A·B·C·D는 1문항, E는 2문항). 유형별 하한이 100%로 나오면 문항 하나의 우연한 실패로 게이트가 실패한다. 결과가 이 경우에 해당하면, 유형별 하한 대신 전체 통과율과 안전·형식·비용 규칙으로 스모크를 운영하도록 `gate.py`를 조정하고, 그 사실과 이유를 결과 문서에 적는다.
- 스모크 6문항의 문항당 토큰은 전체 문항 평균과 구성이 달라 구조적으로 차이가 날 수 있다. 위 25% 여유는 이 차이까지 포함한 값이다.
