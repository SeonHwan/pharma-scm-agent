## 4. 원인 분석 (Langfuse 트레이스, 판정과 무관)
- M은 S보다 호출이 많을 수밖에 없다: 감독의 위임 결정, 전문가의 도구 호출과 보고 작성, 감독의 종합이 각각 LLM 호출이다. 짧은 문항(Y, Z)에서도 비용이 2배인 이유다.
- **L에서 기대한 "컨텍스트 분리로 절감"은 나타나지 않았고, 오히려 결품 조회가 S의 약 2~2.5배였다**(예: L01 `get_shortage` S 93회, M 238회). 트레이스를 보면:
  - 결품 담당이 90개 성분의 상태 목록을 글로 보고하다가 **출력 상한(max_tokens 2048)에 걸렸다.** 이 모델은 사고(thinking) 토큰도 같은 상한 안에서 쓰므로, L01 한 문항에서만 2,048토큰에 닿은 생성이 5개였다.
  - 그 결과 **위임 99건 중 9건(모두 L)의 보고가 비어** 감독에게 돌아갔고, 감독이 같은 성분을 다시 맡기거나 더 작게 나눠 다시 맡겼다. 이 재위임이 조회와 비용을 늘렸다.
  - 정답은 결국 맞혔다(감독이 재위임으로 복구). 대신 지연이 L 중앙값 148초가 됐다.
- 즉 이 구조의 약점은 **전문가가 큰 결과를 글로 넘기는 경계(핸드오프)**다. S는 도구 결과를 그대로 컨텍스트에 두므로 이 손실이 없다.
